# Bubble Tea Shop

## Какой проект запускать

- Магазин написан на Flutter. Открывайте каталог с `pubspec.yaml` и запускайте `lib/core/main.dart`.
- `composeApp/` и `iosApp/` относятся к шаблону Kotlin Compose Multiplatform. APK из `composeApp/build/` собирает шаблонный модуль `org.example.project`. Android-модуль Flutter находится в `android/`.

## Команды

Выполняйте из корня проекта:

```sh
flutter pub get
flutter devices
flutter run -d <device-id> -t lib/core/main.dart
flutter run -d chrome -t lib/core/main.dart
flutter analyze
flutter test
```

Для APK самого магазина используйте `flutter build apk --debug -t lib/core/main.dart`. Web-запуск подходит для быстрой проверки интерфейса. Для отчёта о мобильном тестировании указывайте фактические устройства, версии ОС и результаты прогона.

## Где менять код

- `lib/core/main.dart` содержит маршруты, выбор стартового экрана и навигацию между каталогом и корзиной. Регистрация зависимостей находится в `lib/core/di/injection_container.dart`.
- `lib/features/auth`, `lib/features/shop` и `lib/features/cart` содержат слои `data`, `domain` и `presentation`. Сохраняйте границы слоёв и используйте существующие Cubit и репозитории.
- Каталог загружается из `assets/data/drinks.json`. Если меняете пути к изображениям, сверяйте их с файлами под `assets/img/` и объявлениями в `pubspec.yaml`.
- Перед изменением экрана напитка проверьте, какой класс открывается из `ShopPage`: сейчас переход ведёт на `DrinkDetailPage`, объявленный в самом `shop_page.dart`.

## Лабораторные работы

- №1–3: требования и план, UX-схемы, анализ устройств и конкурентов. Сверяйте состав отчёта с PDF соответствующего задания.
- №4–6: описание и скриншоты модулей, подготовка медиа, показ изображений в приложении. Каталог и PNG-ресурсы уже есть в проекте.
- №7–9: прототип по гайдлайнам и его перенос во Flutter, тестирование на нескольких устройствах, описание, скриншоты и видео для подготовки к публикации.
- При проверке начального состояния учитывайте, что `Checkout` пока имеет пустой обработчик, маршрут восстановления пароля отсутствует, а текущий `CartCubit` держит корзину в памяти. Наличие кода Google Sign-In не подтверждает его работу на устройстве. В `test/widget_test.dart` нет активных тестов.

## Изменения в Git

- Перед коммитом проверьте `git status --short` и `git diff --cached`. Стадируйте нужные файлы явно. Gradle-кэш, файлы из `composeApp/build/` и машинные настройки `local.properties` уже отслеживаются и могут меняться при запуске IDE или сборки.
- Храните ключи подписи и пароли вне репозитория. Текущая Android-конфигурация Flutter использует debug-подпись для release-сборки.
