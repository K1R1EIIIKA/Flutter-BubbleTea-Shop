# Лабораторные работы №3–9. Biba & Boba

Для работ использован Android-модуль Flutter-магазина `com.example.labs`. Проверки проводились на эмуляторах Android 17 (API 37, `emulator-5554`) и Android 15 (API 35, `emulator-5560`), оба x86_64. Точка входа Flutter находится в `lib/core/main.dart`.

## №3. Жизненный цикл

`MainActivity` записывает в Logcat события `onCreate`, `onStart`, `onResume`, `onPause`, `onStop`, `onDestroy`, сохранение состояния и смену конфигурации. У каждой записи есть идентификатор экземпляра Activity. `ScreenLogObserver` записывает отдельные события навигации Flutter.

```powershell
adb -s emulator-5554 logcat -s BubbleTeaLifecycle:I flutter:I
```

| Сценарий | Последовательность из Logcat |
|---|---|
| Холодный запуск | `onCreate restored=false → onStart → onResume`. |
| Из каталога в карточку и обратно | `pause / → show /drink → close /drink → return /`. За это время Activity осталась в `onResume`. |
| Домой и обратно в приложение | `onPause → onStop → onSaveInstanceState → onStart → onResume` у одного экземпляра. |
| Поворот и возврат в портретный режим | `onConfigurationChanged orientation=2 → orientation=1` у одного экземпляра. Конфигурацию обрабатывает Flutter Activity. |
| Выход из каталога кнопкой «Назад», затем новый запуск | `onPause → onStop → onDestroy finishing=true`, затем `onCreate restored=false → onStart → onResume` у нового экземпляра. |
| Уничтожение фонового процесса через `adb shell am kill com.example.labs`, затем открытие прежней задачи | До завершения процесса Android вызвал `onSaveInstanceState`. В новом процессе записано `onCreate restored=true → onStart → onResume`. |

Навигация Flutter меняет экран внутри Activity. При завершении процесса Android может оборвать его без вызова `onDestroy`.

[Жизненный цикл Activity](https://developer.android.com/guide/components/activities/activity-lifecycle)

## №4. Каталог из локального JSON

Источник каталога — `assets/data/drinks.json`. На Android при первом запуске экран может сразу прочитать этот файл. После заполнения кэша экран читает снимок из Room. Есть индикатор загрузки, состояние пустого каталога, сообщение об ошибке с кнопкой повтора и ручное обновление жестом вниз. Ошибка обновления сохраняет уже показанный каталог.

## №5–6. Избранное и личное фото

Сердечко в карточке сохраняет напиток в избранное или снимает отметку. Фильтр «Избранное» в каталоге показывает сохранённые напитки. Для связи используется стабильное оригинальное имя из JSON. Перевод для экрана можно менять независимо.

В блоке «Моё фото» системное окно Android выбирает изображение до 10 МиБ. После выбора приложение копирует файл в приватный каталог `files/drink-photos` и записывает относительный путь в Room. Карточка позволяет показать, заменить и удалить фото. Отмена выбора оставляет предыдущее фото. Фото и отметка избранного изменяются независимо.

На Android 17 напиток «Манго» появился в фильтре «Избранное». Для него выбрано фото из папки Download. После удаления исходного файла и перезапуска приложения отметка и изображение остались на карточке.

## №7. Фоновое обновление

`CatalogRefreshWorker` регистрирует одну периодическую задачу с интервалом 15 минут. Worker читает тот же JSON из пакета приложения, проверяет структуру и сохраняет снимок каталога в Room. При изменении снимка Room уведомляет Flutter через канал событий. Избранное и ссылки на фото хранятся в другой таблице и сохраняются при обновлении.

Локальному источнику сеть не требуется. При временной ошибке чтения задача запрашивает повтор. Отсутствующий файл и некорректная структура приводят к завершению с ошибкой и сохраняют последний валидный снимок. Период 15 минут задаёт минимальный интервал. Время фактического запуска зависит от планировщика, энергосбережения и состояния устройства. При принудительной остановке пакета из настроек возобновление фоновых задач нужно проверять после следующего запуска приложения. Поскольку JSON поставляется в составе APK, новые данные попадают на устройство с новой сборкой.

Первый запуск Worker на Android 15 в авиарежиме записал `Catalog saved to Room` и `Worker result SUCCESS`. На Android 17 приложение свернули и завершили его фоновый процесс через `am kill`. После наступления планового срока задание запустили командой `cmd jobscheduler run -s`, которая запускает его при выполненных системных условиях. В Logcat зафиксированы повторная запись каталога и `SUCCESS` с тем же идентификатором WorkManager. На экране в этот момент оставался Android Launcher.

[Периодические задачи WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work#schedule_periodic_work)

## №9. WebView

Кнопка «Новости» над популярными напитками открывает локальные статьи. Совместимый Android WebView отображает HTML, сформированный из тех же статей, что и резервный экран Flutter. Системная кнопка «Назад» возвращает к каталогу.

На Android 15 с WebView `124.0.6367.219` проверено открытие новостей в авиарежиме. На Android 17 провайдер `158.0.8127.46` на x86_64 вызывал нативный сбой `SIGSEGV` в потоке Chromium. После исправления на этом эмуляторе статьи открылись во Flutter. Переход в новости и возврат в каталог прошли без перезапуска процесса.
